用 Cursor 維護 aogl.cn 的一週：提交節奏 × 片段編輯 × AdSense 整改

本人實踐 · AI agent · 片段手改 · 不自動化的邊界

2026-09-14 · 本站原創

這是用 Cursor 與其它 AI coding agents 維護 aogl.cn 的一週第一人稱手記。不是廠商軟文，不是「十倍工程師」幻想，也不宣稱代理能替代判斷。題圖複用本站已有歸檔 original/img2threejs/bmx-endurance.png——那條流水線本身就是我在本域上線過的 AI 輔助作品。日期 2026-09-14。

這一週實際長什麼樣

多數會話不是從零寫 App，而是外科手術：改文章 JSON 樞紐、加厚英/中片段、把 slug 前置進 data/tech-hub-articles.json 或 data/life-hub-articles.json、清掉殘留的 Google 搜索藥丸、確認頁面不在 ARTICLE_ARCHIVE_NOINDEX_SLUGS 裡，然後才考慮構建。Cursor 在任務合同清晰時很強——「只改這些片段，不要跑 build-site，做完打印字數。」當我含糊說「讓 AdSense 開心一點」卻不點名策略文件時，它會飄。

提交節奏故意無聊：需要時才做小主題提交，不順手重排五十張無關 Hub 卡，不演強制推送。代理起草；是否進入歷史仍由我定。週中我拒絕過幾次「好心」的語種樹批量重生，因為半成品散文會被 build-seo-locale-pages.mjs 覆蓋。

片段編輯才是真正的手藝面

在 aogl.cn，耐久正文在 data/articles/fragments/*-en.html 與 *-zh.html，不在生成出來的 /en/articles/ 鏡像。改錯層的代理會造成信心劇場：預覽好看，下次語種拆分就沒了。本週經驗法則：

  1. 先改 JSON 元數據與片段。
  2. ja/ko/fr/ru/ar 短存根故意保持短。
  3. 藥丸只鏈 App URL 與 /articles/index.html——絕不發明 Google 搜索芯片。
  4. 只有目標是發佈 HTML 時才跑封面生成或 build-articles。
  5. 聲稱「主內容」前先重讀 scripts/seo-index-policy.mjs。

厚雙語正文才是 AdSense 審閱權重。要求代理「七語全量長譯」浪費代幣，還會產出假裝成長文的稀泥存根。更好的做法：一篇誠實 EN ≥900 詞、一篇誠實 ZH ≥1400 漢字、五張短語種卡片。

AdSense 整改閉環（誠實版）

整改是閉環，不是按鈕。本週閉環大致是：

  • 識別薄表面——已在 ARTICLE_ARCHIVE_NOINDEX 的榜單存檔；不要當主 Demo 推。
  • 上厚原創——EatToday / WordPet / 世界之最那種第一人稱頁，帶真實 original/ 截圖。
  • 廣告繼續門禁——js/adsense.js 只在可索引文章 / about / changelog 請求發佈商腳本。
  • 首頁繼續安靜——沿用 adsense-slim-outbound.mjs 的瘦外鏈思路；書籤牆不冒充內容。
  • 改完再核對——新 slug 不得誤入 noindex 集合；robots meta 與加載器行為必須一致。

代理擅長在倉庫裡搜 ARTICLE_ARCHIVE_NOINDEX、isContentPrimaryPage、藥丸標記。它們不擅長判斷一段話到底是第一人稱證據還是關鍵詞湯。每晚這項判斷仍歸我。

我拒絕自動化的邊界

  • 起草階段盲目全量 build-site——寫手太多，覆蓋風暴一次就夠。
  • 不讀補丁就自動提交代理 diff——尤其 ads.txt、策略集合、Hub 成員資格。
  • 發明截圖歸檔——original/ 沒有界面，文章就不假裝有。
  • 把短存根批量灌成假長文——短語種是功能，不是缺陷。
  • 讓代理靠堆外鏈「修 AdSense」——整改方向是更少低價值外鏈、更厚原創。

Cursor 真正賺到工錢的地方

重複機械活：七語標題字段對齊、確認 Hub JSON 前置沒有把已降權的 apple-iphone / pc-standalone 類清單重新加回來、寫 heroImageSource 前核驗圖片路徑存在、草稿後統計詞數/漢字。它也幫我引用真實腳本文件名，而不是憑記憶轉述——當公開長文聲稱流水線真實時，這一點很重要。

需要成人監督的是語氣。第一人稱產品手記若接受第一版「光滑段落」，很容易滑成冊子腔。我反覆要求寫硬邊界（「這不是營養建議」「戰力≠英語成績」「不承諾 AdSense 過審」），因為審閱者聞炒作比聞語法錯誤更快。

七天後的結論

對有嚴格寫作合同的靜態多語言站，AI coding agents 是利器。它們放大片段吞吐與策略搜索。它們不擁有內容分級決策——可索引原創 vs noindex 存檔——也不該擁有發佈按鈕。若你維護類似 aogl 的棧：給代理文件級任務並寫明非目標，然後讓人審廣告策略、Hub 成員資格，以及截圖是否仍匹配正文。

落到可粘貼進 Cursor 提示詞的週末清單，其實很短：核驗題圖路徑存在；確認 Hub 前置；拒絕 Google 藥丸；英/中保持厚度；其它語種保持存根；非發佈階段不跑全站構建；結束時打印詞數與漢字數。這張清單比再寫一篇「人機協作宣言」有用。這一週算成功，是因為倉庫多了誠實的主內容編輯稿，而不是因為聊天記錄看起來聰明。

我也刻意觀察了代理容易越界的幾類改動：把 life Hub 裡的存檔榜單重新抬成「好 Demo」；在技術手記裡插入未經驗證的截圖路徑；為了湊字數把短語種擴成機翻長文；以及在未讀 js/adsense.js 的情況下斷言「首頁也應該出廣告」。這些越界一旦進 git，清理成本高於當時省下的十分鐘。所以我的習慣是：代理可以起草，策略與 Hub 成員資格必須人點頭，發佈構建必須人觸發。

若把這一週濃縮成一句話：用 Cursor 加速 aogl.cn 的片段工程與策略檢索，但把「什麼算可索引原創」堅決留在人類側。題圖選用 img2threejs 歸檔，是為了提醒自己——本站本來就有 AI 輔助作品線；維護編輯站時，更要把同樣的誠實標準用在文字與廣告策略上，而不是隻在炫技 Demo 裡認真。
