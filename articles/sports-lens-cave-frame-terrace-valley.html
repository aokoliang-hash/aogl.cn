洞穴框景 × 梯田樱谷：长焦窗框风光合成手记

jib1od · 1frod · video.mp4 · 框中框构图

2026-06-22 · 本站原创

这是 aogl.cn 归档的第 16 篇原创手记，素材在 original/sports-lens/。项目代号「sports-lens」指的是长焦/窗框式取景练习——用洞穴口当天然暗角画框，框住梯田、樱树、河流与远山雾带，再导出 MP4 看「框中框」在运动时是否仍成立。不是某省某县旅游宣传，也不标注真实 GPS；只记录文件名、构图决策与和站内其他「窗框线」文章的差异。

  • Gemini_Generated_Image_1frod41frod41fro.png — 同题材探索帧 A：框缘岩石与雾浓度略不同
  • Gemini_Generated_Image_1frod41frod41fro1.png — 探索帧 B：樱色饱和度与水面反光微调
  • video.mp4 — 主成片（2026-06-22 更新）
  • video-2.mp4 — 第二轮导出：对比框缘暗部与云带漂移

标题与图注里会出现真实检索词：cave frame landscape、terrace rice fields、cherry blossom valley、natural window composition、frame-in-frame video——均对应磁盘上的画面，不是无关热词堆砌。

为什么做「洞穴框景」而不是全画幅风景

站内已有 高铁车窗、客机舷窗云海 与 公寓 360° 全景。本篇补的是有机暗框：窗框不是矩形玻璃，而是不规则岩洞轮廓，前景几乎全黑，观众先读到「我在看一个被限定的视野」，再进入谷地叙事。心理学上，这种窥视/发现秘境的构图比平铺全景多一层「藏」与「揭」。

我把前景洞穴地面留了一小丛粉白野花——不是写实植物志，而是给绝对暗部一个尺度锚点：没有它，岩框会像纯 vignette 滤镜；有它，人眼会接受「相机在洞内、主体在洞外」的空间分层。

定稿静帧 jib1od：封面为什么选它

三张 PNG 里，jib1od 的框缘对比最强：顶部垂下的藤条与岩齿把天空切成不规则拱门，中间谷地亮度最高，远峰与低云形成第二条水平线。1frod 系列在樱色偏品红或雾太厚时我会保留为本地对照，但不作轮播封面——缩略图需要 16:9 下一眼读出「框+谷」，而不是「一片粉色树林」。

两张 1frod 探索帧：我在改什么

生成式出图常见问题是框缘漂移：洞口的岩石厚度一变，整个透视故事就崩。1frod 与 1frod1 是我同 prompt 方向下的两次保留，用来对比：

  • 1frod — 框缘更宽、暗部更占画面；适合测试「暗角是否压过主体」
  • 1frod1 — 河谷水面更亮、樱树更密；适合测试「高光会不会假到像 HDR 滤镜」

两者都没有替换 jib1od 成为 hero，因为文章需要一张最稳的默认叙事帧；探索帧只服务本地 before/after，不增加访客认知负担。

谷地元素：梯田、樱树、河、雾

画面中段是阶梯梯田与水面反光——我刻意不写成「元阳」「龙脊」等真实地名，因为文件并未绑定测绘数据。樱树成片是为了提供季节色块：在缩略图里与绿色梯田形成互补，让「框中框」内部仍有第二层视觉节奏。

远峰与低云（或晨雾）负责纵深：如果只有中景梯田，洞穴框会显得像贴图；有了第三条大气透视线，观众才会把谷地读成「可走进去的世界」，而不是一张平面插画。

video.mp4 与 video-2.mp4

静帧可以靠构图骗人，视频会暴露框缘是否闪烁、樱树是否有不合逻辑的抖动、云雾是否像循环贴图。主成片 video.mp4 是 2026-06-22 重新导出的版本；video-2.mp4 保留较早一轮参数，方便我对照「暗部是否发灰」「河面高光是否过曝」。

和站内其他「窗框线」怎么分工

  • 高铁车窗 — 人造矩形窗 + 运动模糊外景
  • 舷窗云海 — 椭圆舷窗 + 高空平流层
  • sports-lens — 有机岩框 + 地面谷地（本页）
  • 穿越视差手机 — 矩形屏幕框 + 分层 PNG

四条线共用同一套验收问题：框是否先于场景被读懂？换场景后框是否仍可信？ 答案为否的素材不会进 git。

工具与边界

静帧来自 Gemini 出图探索；文件名保留 Gemini_Generated_Image_… 以便和 girl1 九格、role-girl 卡牌 一样可追溯批次。我不在文中复述 vendor prompt，也不教「一键生成 Shangri-La」。若你 fork 做纪实摄影，应替换为可核实的拍摄地点与 EXIF，而不是沿用本文件夹的虚构谷地。

出图后我只在本地做裁剪与视频导出；HTML 文章负责诚实说明范围。这与 AdSense 阶段「articles 为主内容」的策略一致：一篇 URL 对应一个可检查的 original/ 目录。

维护约定

  1. 换 hero PNG → 重跑 npm run generate-article-covers 并更新 dateModified。
  2. 新增探索帧 → 只加入 gallery，不自动替换 hero，除非框缘故事更清楚。
  3. 不在 hub-links 或 briefs 重复发同一组图；长文只驻留 articles/。

下一篇若继续「框景线」，可能是废弃塔楼窗洞或桥洞框架——仍须先有过关静帧与 MP4，再写 scope 段落；不会为凑 17 篇而复制本页结构。
