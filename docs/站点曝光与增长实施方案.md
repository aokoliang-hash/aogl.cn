# aogl.cn 站点曝光与增长实施方案（面向全球）

> **定位**：个人维护的生成式 AI 备忘站（聚合外链 + 少量原创）。增长目标应是「**可被需要的人稳定找到**」，而非流量竞赛。  
> **本文默认**：主要受众在**全球**（英语及各语种 hub），搜索引擎与分发以 **Google / Bing 生态**为主；国内百度等为**可选**补充。  
> **技术基线**：静态 HTML、多语言、`hreflang`、`sitemap.xml`、首页与文章区已有 SEO 基建；更细的原创与结构化数据要求见同目录 [`首页原创文章与SEO实施说明.md`](./首页原创文章与SEO实施说明.md)。

---

## 1. 目标与成功标准

| 维度 | 建议目标（3～6 个月） | 说明 |
|------|------------------------|------|
| **可发现性** | 品牌词「aogl」与各文章 slug 在 Google/Bing 可检索 | 先做「搜得到」，再谈泛词排名 |
| **收录** | 根站与各语言首页、重要 hub、`articles/*.html` 被收录；新文 2～4 周内出现在 GSC/Bing | 依赖 sitemap、内链与 `hreflang` |
| **自然访问** | 英文/多语长尾（工具名 + bookmark / hub / notes 等）有少量稳定展示与点击 | 与**可索引的英文标题与正文块**强相关 |
| **社交/外链** | GitHub、X、Reddit、HN 等在**合规、先贡献价值**的前提下自然带出链接 | 不追求灌水外链 |

## 2. 全球受众与渠道优先级

### 2.1 主渠道（建议必做）

| 渠道 | 用途 |
|------|------|
| [Google Search Console](https://search.google.com/search-console) | 收录、查询词、点击率、国际定向问题、Core Web Vitals 摘要 |
| [Bing Webmaster Tools](https://www.bing.com/webmasters) | 补充索引与报错；可一键导入 GSC 数据 |
| **GitHub** | 仓库 README、开源 demo 的权威出站链接，全球开发者可见 |
| **个人简介统一露出** | X、LinkedIn、Mastodon、Reddit profile 等：一句话 + `https://aogl.cn/` |

### 2.2 次级渠道（按精力选做）

| 渠道 | 适用 |
|------|------|
| [Yandex Webmaster](https://webmaster.yandex.com/) | 若关心俄语区展示（本站已有 `/ru/`） |
| [Naver Search Advisor](https://searchadvisor.naver.com/) | 若刻意运营韩语内容（本站已有 `/ko/`） |
| **IndexNow**（经 Bing 或插件提交） | 加速新 URL 被发现；需服务器或构建侧支持 ping，非必须 |

### 2.3 可选：国内中文补充

若仍希望兼顾大陆检索，可**额外**注册百度搜索资源平台并提交 sitemap；与全球策略并行即可，不替代 GSC/Bing。

## 3. 分阶段实施计划

### 阶段 A：测量与站长工具（第 1～2 周）

**目的**：建立全球流量基线，确保国际爬虫无拦阻。

1. **安装并验证（优先顺序）**
   - **Google Search Console**：域名资源（推荐）或 `https://aogl.cn/` 前缀验证。
   - **Bing Webmaster Tools**：验证后使用「Import from Google Search Console」节省时间。
   - 按需：**Yandex** / **Naver**（见 §2.2）。

2. **上线后立即做的几件小事**
   - 在 GSC 对首页、`/en/`、1～2 篇代表性文章使用 **URL Inspection → Request indexing**（仅作启动助推，日常仍靠 sitemap）。
   - 确认 `sitemap.xml` 可被公开访问且包含各语言首页与重要文章 URL。

3. **自检清单**
   - `robots.txt` 未误拦全站；全站 **HTTPS**；无大量 5xx/长链重定向。
   - 各语言首页与文章页的 **`hreflang` 与 `canonical` 一致**（避免「英文内容却 canonical 到中文根站」类问题）；细则见 SEO 实施说明中的多语策略。
   - 文章页有独立 **`title` / `meta description` / `og:*`**，分享至 X/Slack 时预览正常。

4. **产出**：表格记录各市场（国家/设备）的展示、点击与抓取错误基线，便于三个月后对比。

---

### 阶段 B：站内 SEO 与全球化内容节奏（持续）

**目的**：让「值得被全球用户搜到」的页面有可索引的**英文（及各语）**信号，并与 URL 结构一致。

1. **执行现有规范**（见《首页原创文章与SEO实施说明》）
   - 长原创：**一文一 URL**；正文在首屏 HTML；`BlogPosting` 等 JSON-LD 建议 **`inLanguage`** 与页面主语言一致。
   - 新文章上线后：**更新 sitemap** `lastmod`；在 GSC/Bing 侧按平台提交或等待周期性抓取。

2. **内容策略（面向全球发现）**
   - **英文元数据**：面向国际传播的文章，至少保证 **英文 `title` / `description` / 首段** 在对应语言版本或 `lang-en` 块中完整、非空，避免爬虫只读到中文而英文 URL 单薄。
   - **固定频率**：例如每月 1～2 篇可独立分享的原创或技术手记（带清晰 slug，便于口头传播）。
   - **选题**：工具导航、个人工作流、WebGL/Three.js 实验等**全球开发者常搜**且重复度适中的主题。
   - **内链**：新文在首页「本站原创」、相关 hub、以及**英文导航路径**中可被发现，避免孤岛页。

3. **RSS**
   - 提供 `application/rss+xml`（可全英或分 feed），便于 Feedly、RSS 读者与聚合站订阅，带来稳定回访与自然引用。

---

### 阶段 C：站外曝光与合规增长（第 2 个月起，长期轻量）

**目的**：在全球社区中建立「可信的个人策展站」认知，而非链接农场。

1. **GitHub**
   - README 首屏用**英文一句**说明价值 + `https://aogl.cn/`；与仓库语言一致更易获 star 与外链。
   - 若有 demo 源码，README **Deep link** 到对应 `articles/*.html` 或 `/en/articles/...`（与构建输出一致即可）。

2. **社区（原则：先解决问题，再分享链接）**
   - **Reddit**：r/MachineLearning、r/LocalLLaMA、r/generativeAI 等需严格遵守各版规；长文可写「Disclosure: personal site」类说明，避免被视作 spam。
   - **Hacker News**：若有**实质性**技术文章或工具，可考虑 **Show HN**；标题 factual，评论区及时回应质疑。
   - **X / Mastodon / Bluesky**：发更新时带清晰截图与一句话价值；简介中固定站点链接。
   - **Dev.to / Hashnode**（可选）：若转载摘要，务必 **canonical 指回 aogl.cn** 正文页，避免重复内容稀释权重。

3. **友情链接**
   - 与英文/多语个人博客、工具导航站**主题相近**的互换即可，贵精不贵多。

---

### 阶段 D：体验与留存（全球访问质量）

**目的**：降低跨国延迟与跳出，利于排名与用户回访。

1. **性能**：Lighthouse / PageSpeed Insights（选 **Mobile + 多国节点**若可用）季度抽测；大图 lazy、关键 CSS 与脚本策略保持轻量。
2. **首屏**：新访客快速理解站点是 **personal AI bookmarks**，非新闻媒体，减少误期望跳出。
3. **多语言**：语言切换与 `hreflang` 保持正确；**分享链接时**默认使用对方能读懂的语言版本 URL（例如给国际圈分享 `/en/` 或英文文章 canonical URL）。

---

## 4. 不建议的做法（风险与性价比）

- 购买外链、互点、流量机器人：Google 质量指南风险高，且与站点调性不符。
- 全文堆在首页、依赖纯前端异步才出正文：不利于收录。
- 同一内容多 URL 无 `canonical`：分散权重、国际站点易出现重复收录。
- 在英文社区**标题党 + 无实质内容**引流：易遭举报、伤品牌。

## 5. 分工与节奏（单人业余版）

| 周期 | 动作 |
|------|------|
| **每周 15 分钟** | GSC + Bing：抓取错误、索引覆盖率、手动检查 1～2 个新 URL 是否已收录。 |
| **每月 1～2 小时** | 一篇面向全球可读的原创或深度整理 + sitemap/内链 + 可选一条合规社区分享。 |
| **每季度** | 对比各国/设备 Top 查询与 CTR；优化 `title`/`description`（不改事实）；抽测 Core Web Vitals。 |
