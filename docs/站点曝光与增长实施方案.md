# aogl.cn 站点曝光与增长实施方案（面向全球 · Google 搜索优先）

> **定位**：个人维护的生成式 AI 备忘站（聚合外链 + 少量原创）。增长目标应是「**可被需要的人稳定找到**」，而非流量竞赛。  
> **搜索引擎策略（本文约定）**：**只主动运营 Google**（[Google Search Console](https://search.google.com/search-console) 验证、sitemap、索引与查询分析）。**不注册、不维护**必应站长、Yandex、Naver 等其它站长平台。  
> **说明**：站点若对公网开放，**其它搜索引擎的爬虫仍可能自行抓取**，这与你是否注册其站长工具无关；本方案仅表示你把**时间与流程**集中在 GSC。  
> **技术基线**：静态 HTML、多语言、`hreflang`、`sitemap.xml`、首页与文章区已有 SEO 基建；更细的原创与结构化数据要求见同目录 [`首页原创文章与SEO实施说明.md`](./首页原创文章与SEO实施说明.md)。

## 1. 目标与成功标准

| 维度 | 建议目标（3～6 个月） | 说明 |
|------|------------------------|------|
| **可发现性** | 品牌词「aogl」与各文章 slug 在 **Google** 可检索 | 先做「搜得到」，再谈泛词排名 |
| **收录** | 根站与各语言首页、重要 hub、`articles/*.html` 被 Google 收录；新文 2～4 周内在 GSC 可见状态更新 | 依赖 sitemap、内链与 `hreflang` |
| **自然访问** | 英文/多语长尾（工具名 + bookmark / hub / notes 等）在 Google 有少量稳定展示与点击 | 与**可索引的英文标题与正文块**强相关 |
| **社交/外链** | GitHub、X、Reddit、HN 等在**合规、先贡献价值**的前提下自然带出链接 | 不追求灌水外链 |

## 2. 全球受众与渠道优先级

### 2.1 主渠道（建议必做）

| 渠道 | 用途 |
|------|------|
| **Google Search Console** | 收录、查询词、点击率、国际定向、Core Web Vitals 摘要 — **唯一必做的搜索引擎后台** |
| **GitHub** | 仓库 README、开源 demo 的权威出站链接，全球开发者可见 |
| **个人简介统一露出** | X、LinkedIn、Mastodon、Reddit profile 等：一句话 + `https://aogl.cn/` |

### 2.2 本方案不覆盖（除非你以后改主意）

| 项目 | 说明 |
|------|------|
| Bing Webmaster、Yandex、Naver 等 | 不验证、不提交、不按其后台排期维护 |
| 百度搜索资源平台 | 同上；仅当你**明确要大陆百度获客**时再单独加 |

## 3. 分阶段实施计划

### 阶段 A：测量与 Google Search Console（第 1～2 周）

**目的**：建立全球流量基线，确保 Googlebot 无拦阻。

1. **安装并验证**
   - **Google Search Console**：域名资源（推荐）或 `https://aogl.cn/` 前缀验证。

2. **上线后立即做的几件小事**
   - 在 GSC 对首页、`/en/`、1～2 篇代表性文章使用 **URL Inspection → Request indexing**（仅作启动助推，日常仍靠 sitemap）。
   - 在 GSC **Sitemaps** 中提交 `https://aogl.cn/sitemap.xml`（若尚未提交）。
   - 确认 `sitemap.xml` 可被公开访问且包含各语言首页与重要文章 URL。

3. **自检清单**
   - `robots.txt` 未误拦全站；全站 **HTTPS**；无大量 5xx/长链重定向。
   - 各语言首页与文章页的 **`hreflang` 与 `canonical` 一致**；细则见 SEO 实施说明。
   - 文章页有独立 **`title` / `meta description` / `og:*`**，分享至 X/Slack 时预览正常。

4. **产出**：在表格或笔记中记录 GSC 各市场的展示、点击与抓取错误基线，便于三个月后对比。

---

### 阶段 B：站内 SEO 与全球化内容节奏（持续）

**目的**：让「值得被 Google 用户搜到」的页面有可索引的**英文（及各语）**信号，并与 URL 结构一致。

1. **执行现有规范**（见《首页原创文章与SEO实施说明》）
   - 长原创：**一文一 URL**；正文在首屏 HTML；`BlogPosting` 等 JSON-LD 建议 **`inLanguage`** 与页面主语言一致。
   - 新文章上线后：**更新 sitemap** `lastmod`；依赖 Google 周期性抓取，必要时对关键 URL 在 GSC 做一次 **Request indexing**。

2. **内容策略（面向全球发现）**
   - **英文元数据**：面向国际传播的文章，至少保证 **英文 `title` / `description` / 首段** 在对应语言版本或 `lang-en` 块中完整、非空。
   - **固定频率**：例如每月 1～2 篇可独立分享的原创或技术手记（带清晰 slug）。
   - **选题**：工具导航、个人工作流、WebGL/Three.js 实验等**全球开发者常搜**且重复度适中的主题。
   - **内链**：新文在首页「本站原创」、相关 hub、以及**英文导航路径**中可被发现，避免孤岛页。

3. **RSS**
   - 提供 `application/rss+xml`，便于 Feedly 等订阅；对 Google 为辅助发现手段，非替代 sitemap。

---

### 阶段 C：站外曝光与合规增长（第 2 个月起，长期轻量）

**目的**：在全球社区中建立「可信的个人策展站」认知，而非链接农场。

1. **GitHub**
   - README 首屏用**英文一句**说明价值 + `https://aogl.cn/`；若有 demo 源码，README **Deep link** 到对应文章页。

2. **社区（原则：先解决问题，再分享链接）**
   - **Reddit**、**Hacker News**、**X / Mastodon / Bluesky**、**Dev.to / Hashnode**（转载须 **canonical 指回 aogl.cn**）— 与搜索引擎是否包含 Bing 无关，属于**直接流量与品牌**。

3. **友情链接**
   - 与英文/多语个人博客、工具导航站主题相近的互换即可，贵精不贵多。

---

### 阶段 D：体验与留存（全球访问质量）

**目的**：降低跨国延迟与跳出，利于 Google 排名与用户回访。

1. **性能**：PageSpeed Insights / Lighthouse（**Mobile**）季度抽测；大图 lazy、关键 CSS 与脚本保持轻量。
2. **首屏**：新访客快速理解站点是 **personal AI bookmarks**，非新闻媒体。
3. **多语言**：语言切换与 `hreflang` 保持正确；对外分享优先给可读语言版本的 URL（如 `/en/`）。

---

## 4. 不建议的做法（风险与性价比）

- 购买外链、互点、流量机器人：Google 质量指南风险高。
- 全文堆在首页、依赖纯前端异步才出正文：不利于收录。
- 同一内容多 URL 无 `canonical`：分散权重、易出现重复收录。
- 在英文社区标题党、无实质内容引流：易遭举报、伤品牌。

## 5. 分工与节奏（单人业余版 · 仅 GSC）

| 周期 | 动作 |
|------|------|
| **每周 15 分钟** | 打开 GSC：抓取/索引报错、覆盖率变化；抽查 1～2 个新 URL 是否在「网页索引」中有状态更新。 |
| **每月 1～2 小时** | 一篇面向全球可读的原创或深度整理 + sitemap/内链 + 可选一条合规社区分享。 |
| **每季度** | 在 GSC 对比各国/设备 Top 查询与 CTR；优化 `title`/`description`（不改事实）；抽测 Core Web Vitals。 |
