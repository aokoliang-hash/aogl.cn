# 站点原创内容与实施节奏（评审稿）

> 本文档为实施指引；**§3 首页**、**§3 更新记录（changelog）**、**§4 各 Hub JSON 导语 / lead** 与 **§5 隐私** 已在仓库落地。其余（短文专栏、Search Console 专项等）可按 §6 排期。

---

## 1. 目的

- 在**不削弱现有自动化能力**（RSS、hub 构建、多语言）的前提下，为首页与各垂直页增加**可读的、站长视角的原创文字**。
- 利于：搜索摘要质量、用户信任、回访理由（「这里有一句人话说明白数据来源」）。

---

## 2. 三条内容原则（全站通用）

| 原则 | 建议 |
|------|------|
| **站长相声** | 每页（或每大块）80～200 字：为什么整理、信息从哪来、不保证什么。 |
| **筛选/更新标准** | 一两句：RSS 怎么合并、榜单依据、工具目录入选或下线标准。 |
| **固定节奏** | 例如每周五：一句「本周更新」+ 一处短文修订；比单次堆长文更有利于长期收录印象。 |

---

## 3. 首页 `index.html`（优先实施）

> **进度**：页首 **「关于本站」**（`#intro` + `.site-intro`，与页脚「关于」同锚点 `#intro`）+ 扩写四张 `.card`、双段 `.tools-intro`、各 `#cat-*` 的 `cat-feed-lead` 已在 **`_multilang/index.html`** 维护；`npm run build-seo-locales` 会写出根目录简体与各语言 `index.html`（含 `/zh/` 繁体）。根目录简体若需与母版不同步，应改 `_multilang` 后再跑构建。

| 位置 | 建议动作 | 备注 |
|------|----------|------|
| **`#pillars` 上方** | 页首 **`#intro` + `.site-intro`**（标题「关于本站」）：面向谁、外链新标签、非商业评测、纠错方式等；与页脚「关于」同锚点，勿再在页底重复一块。 | 纯 HTML 手改；注意与 `inject-index-pills` 等脚本的**注释区间**别被覆盖。 |
| **四张 `.card`** | 每张从一句话扩成 **2～3 句原创**：各 `#cat-*` 区块里读者能期待什么、你如何选链。 | 同上，手改 `index.html`。 |
| **`#tools-directory` 的 `.tools-intro`** | 扩写：**分类逻辑**、不收录什么、纠错方式（邮件 / GitHub issue 一句）。 | 手改。 |
| **各 `#cat-*` 标题下** | 若已有 lead 段落则加长；没有则各加 **一句**「本周侧重点」或编辑备注。 | 视现有结构而定。 |
| **更新记录（可选）** | 新增 `changelog.html` 或首页锚点区块，3～5 条人类可读更新。 | **已做**：`_multilang/changelog.html` + 各语言构建输出；首页与各 Hub 页脚链至 `changelog.html`；`sitemap.xml` 已收录。 |

**实施顺序建议**：先做「关于本站」+ 四张卡片 + `tools-intro`，投入小、收益相对高。

**多语言**：以 **`_multilang/index.html`** 为母版维护各 `lang-*` 段落，执行 `npm run build-seo-locales` 生成 `/en/`、`/ja/`、`/zh/`（繁体）等目录下的 `index.html`；根目录简体首页由同一脚本从母版剥离 `lang-zh` 写出。

## 4. 各 Hub 垂直页

> **进度**：`data/hubs` 下 portal / brands / shopping / life / social / tech / games / tools 已扩写 **`editorialHtmlEn|Zh`**（多为两段），并补全 **`rankLead` / `newsLead` / `moreLead`**（及 games 的 **hotMixLead** 一句）；`scripts/build-hub-pages.mjs` 中 **`EDITORIAL_I18N`** 的 ja/ko/fr/ru/ar 已加长为与英文同主题的**第二段**。改完后执行：

```bash
npm run build-hubs
npm run build-seo-locales
```

| 页面 / slug | 建议原创重点 |
|-------------|----------------|
| **portal** | 流量前十与公开榜单（Similarweb、Radar 等）的关系；不做实时排名承诺；多久对照一次。 |
| **brands** | 品牌价值类榜单的常见来源；**非投资建议** 写清楚。 |
| **shopping** | 电商前十的地域偏差；「更多」里中国平台的放置理由。 |
| **life** | 「数字生活」边界（地图/支付/出行等）；避免医疗诊断类表述。 |
| **social** | MAU 类数据滞后性；编辑取舍（为何不放某类 App）一两句。 |
| **tech** | 与 portal 的区分（偏公司与半导体叙事）；**非投资建议**。 |
| **games** | Hot mix 的 RSS 来源与合并规则；更新频率；英文标题为主的原因（若仍如此）。 |
| **tools** | 外链工具免责声明；为何是「天气/日历」这类精选而非海量堆链。 |

**「更多」区块**：若 JSON 有 `moreLead` 或类似字段，可扩写 2～3 句；若无，可在构建模板中增加（**属开发项**，需改 `scripts/build-hub-pages.mjs` 与各 spec）。

## 6. 四周节奏（可选执行表）

| 周次 | 任务 |
|------|------|
| **第 1 周** | 首页：关于本站 + 四卡片 + `tools-intro`；`games`、`portal` 导语各扩一段。 |
| **第 2 周** | 其余 hub JSON 导语各补一段；首页各 `#cat-*` 下一句话编辑说明。 |
| **第 3 周** | 选一个分类写 500～800 字短文（可仍在首页该区块上方，或将来独立文章页）。 |
| **第 4 周** | 根据 Search Console 展现/点击，只优化 2～3 个重点页的标题、首段、`meta description`（与各语言 `data-title-*` / `data-desc-*` 策略协调）。 |

---

## 7. 风险与注意

- **首页**：若运行 `npm run build-index-pills` 或其它会写 `index.html` 的脚本，**先备份**或确认脚本不会覆盖你手写的 `section`。
- **Hub**：只改 JSON 再构建，**不要**长期手改生成的 `portal.html` 等，否则下次构建会丢。
- **语气**：保持现有站点的克制风格（业余备忘、非评测机构），与隐私/广告说明一致。

---

## 8. 不实施时

- 站点仍可正常运作；仅为**增长与信任**层面的增强项，无强制依赖。

---

## 9. 若你决定实施，可交给开发的具体工单（示例）

1. 在 `index.html` 增加 `#intro` + `.site-intro` 区块（约 120 字中文）+ 样式沿用 `style.css` 现有段落类；与页脚「关于」同一锚点，避免页底再写一块「关于本站」。
2. 扩写四处 `.card` 与 `.tools-intro` 文案（中文）。  
3. 编辑 `data/hubs/portal.json`、`games.json` 等对应字符串 → `npm run build-hubs && npm run build-seo-locales`。  
4. （可选）新增 `changelog.html` 与首页页脚链接。
