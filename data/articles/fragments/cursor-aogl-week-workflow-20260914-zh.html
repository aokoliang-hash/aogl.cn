这是用 Cursor 与其它 AI coding agents 维护 aogl.cn 的一周第一人称手记。不是厂商软文，不是「十倍工程师」幻想，也不宣称代理能替代判断。题图复用本站已有归档 original/img2threejs/bmx-endurance.png——那条流水线本身就是我在本域上线过的 AI 辅助作品。日期 2026-09-14。

这一周实际长什么样

多数会话不是从零写 App，而是外科手术：改文章 JSON 枢纽、加厚英/中片段、把 slug 前置进 data/tech-hub-articles.json 或 data/life-hub-articles.json、清掉残留的 Google 搜索药丸、确认页面不在 ARTICLE_ARCHIVE_NOINDEX_SLUGS 里，然后才考虑构建。Cursor 在任务合同清晰时很强——「只改这些片段，不要跑 build-site，做完打印字数。」当我含糊说「让 AdSense 开心一点」却不点名策略文件时，它会飘。

提交节奏故意无聊：需要时才做小主题提交，不顺手重排五十张无关 Hub 卡，不演强制推送。代理起草；是否进入历史仍由我定。周中我拒绝过几次「好心」的语种树批量重生，因为半成品散文会被 build-seo-locale-pages.mjs 覆盖。

片段编辑才是真正的手艺面

在 aogl.cn，耐久正文在 data/articles/fragments/*-en.html 与 *-zh.html，不在生成出来的 /en/articles/ 镜像。改错层的代理会造成信心剧场：预览好看，下次语种拆分就没了。本周经验法则：

  1. 先改 JSON 元数据与片段。
  2. ja/ko/fr/ru/ar 短存根故意保持短。
  3. 药丸只链 App URL 与 /articles/index.html——绝不发明 Google 搜索芯片。
  4. 只有目标是发布 HTML 时才跑封面生成或 build-articles。
  5. 声称「主内容」前先重读 scripts/seo-index-policy.mjs。

厚双语正文才是 AdSense 审阅权重。要求代理「七语全量长译」浪费代币，还会产出假装成长文的稀泥存根。更好的做法：一篇诚实 EN ≥900 词、一篇诚实 ZH ≥1400 汉字、五张短语种卡片。

AdSense 整改闭环（诚实版）

整改是闭环，不是按钮。本周闭环大致是：

  • 识别薄表面——已在 ARTICLE_ARCHIVE_NOINDEX 的榜单存档；不要当主 Demo 推。
  • 上厚原创——EatToday / WordPet / 世界之最那种第一人称页，带真实 original/ 截图。
  • 广告继续门禁——js/adsense.js 只在可索引文章 / about / changelog 请求发布商脚本。
  • 首页继续安静——沿用 adsense-slim-outbound.mjs 的瘦外链思路；书签墙不冒充内容。
  • 改完再核对——新 slug 不得误入 noindex 集合；robots meta 与加载器行为必须一致。

代理擅长在仓库里搜 ARTICLE_ARCHIVE_NOINDEX、isContentPrimaryPage、药丸标记。它们不擅长判断一段话到底是第一人称证据还是关键词汤。每晚这项判断仍归我。

我拒绝自动化的边界

  • 起草阶段盲目全量 build-site——写手太多，覆盖风暴一次就够。
  • 不读补丁就自动提交代理 diff——尤其 ads.txt、策略集合、Hub 成员资格。
  • 发明截图归档——original/ 没有界面，文章就不假装有。
  • 把短存根批量灌成假长文——短语种是功能，不是缺陷。
  • 让代理靠堆外链「修 AdSense」——整改方向是更少低价值外链、更厚原创。

Cursor 真正赚到工钱的地方

重复机械活：七语标题字段对齐、确认 Hub JSON 前置没有把已降权的 apple-iphone / pc-standalone 类清单重新加回来、写 heroImageSource 前核验图片路径存在、草稿后统计词数/汉字。它也帮我引用真实脚本文件名，而不是凭记忆转述——当公开长文声称流水线真实时，这一点很重要。

需要成人监督的是语气。第一人称产品手记若接受第一版「光滑段落」，很容易滑成册子腔。我反复要求写硬边界（「这不是营养建议」「战力≠英语成绩」「不承诺 AdSense 过审」），因为审阅者闻炒作比闻语法错误更快。

七天后的结论

对有严格写作合同的静态多语言站，AI coding agents 是利器。它们放大片段吞吐与策略搜索。它们不拥有内容分级决策——可索引原创 vs noindex 存档——也不该拥有发布按钮。若你维护类似 aogl 的栈：给代理文件级任务并写明非目标，然后让人审广告策略、Hub 成员资格，以及截图是否仍匹配正文。

落到可粘贴进 Cursor 提示词的周末清单，其实很短：核验题图路径存在；确认 Hub 前置；拒绝 Google 药丸；英/中保持厚度；其它语种保持存根；非发布阶段不跑全站构建；结束时打印词数与汉字数。这张清单比再写一篇「人机协作宣言」有用。这一周算成功，是因为仓库多了诚实的主内容编辑稿，而不是因为聊天记录看起来聪明。

我也刻意观察了代理容易越界的几类改动：把 life Hub 里的存档榜单重新抬成「好 Demo」；在技术手记里插入未经验证的截图路径；为了凑字数把短语种扩成机翻长文；以及在未读 js/adsense.js 的情况下断言「首页也应该出广告」。这些越界一旦进 git，清理成本高于当时省下的十分钟。所以我的习惯是：代理可以起草，策略与 Hub 成员资格必须人点头，发布构建必须人触发。

若把这一周浓缩成一句话：用 Cursor 加速 aogl.cn 的片段工程与策略检索，但把「什么算可索引原创」坚决留在人类侧。题图选用 img2threejs 归档，是为了提醒自己——本站本来就有 AI 辅助作品线；维护编辑站时，更要把同样的诚实标准用在文字与广告策略上，而不是只在炫技 Demo 里认真。
