This is the ninth original article on aogl.cn, sourced from original/360-degree-panorama/. I built an embeddable apartment interior 360° tour: four 2:1 equirectangular panoramas, one panorama-viewer.html shell, and a Three.js sphere with inverted normals so the camera sits inside the room. Hotspots jump between living room, dining room, kitchen, and master bedroom. It is not a brokerage landing page and not a vendor tutorial—only how this demo is wired and what I would change next time.

What is in the folder

  • Living-room.png — Nordic-style living room, park view through tall windows
  • dining-room.png — formal dining space with chandelier and long table
  • kitchen.png — island kitchen, marble counter, copper cookware on display
  • master-bedroom.png — bedroom suite with city skyline glazing
  • panorama-viewer.html — full-screen tour UI (drag, zoom, scene list)

Each image is a full 360° horizontal sweep at roughly 2:1 width-to-height—the usual equirectangular layout for panorama textures. If the ratio drifts, you get a visible seam or stretched floor/ceiling bands. I sanity-check left and right edges before committing a file to the repo.

Why an inverted sphere

The common Three.js pattern is SphereGeometry plus scale(-1, 1, 1), camera near the origin, and lookAt driven by yaw and pitch. You are not orbiting furniture from outside; you are standing in the room and turning your head. Drag updates view direction; the sphere mesh stays put.

That rhymes with the site’s interactive 3D Earth (also WebGL + Three.js r128) but the earth looks from outside with lights and atmosphere. Interior tours only need MeshBasicMaterial and one texture map—cheaper and avoids flattening baked lighting in the panorama.

Four scenes and hotspot types

Configuration lives in a SCENES array inside panorama-viewer.html. Per scene: id, display name, short description, image filename, optional initYaw / initPitch, and a hotspots list.

Hotspots are grouped by role (color-coded in the UI):

  • entry — jump to another room (e.g. living room → dining room)
  • exit — go back to the previous space
  • info — modal copy about architecture or views (windows, chandelier, skyline)
  • poi — furniture or fixture notes (sofa, island, wardrobe)

Each hotspot stores yaw and pitch in degrees, plus either targetScene or an info string. On screen, positions are projected from sphere coordinates; markers behind the viewer hide so the frame does not fill with buttons.

UI pieces worth naming for SEO

The top bar shows the active scene title; a collapsible left rail lists all four spaces with 16:9 thumbs from the same PNGs. A compass widget rotates with yaw so “north” in the UI is not magic—it is tied to -yaw on the needle. Bottom controls expose FOV in degrees (roughly 35°–115°), previous/next scene, and toggles for autoplay (nine-second interval by default) and slow auto-rotate while you are not dragging.

Keyboard arrows nudge view direction; + / - zoom; r resets to each scene’s initYaw. If a texture fails to load, the viewer falls back to a labeled gradient canvas so the hotspot graph still makes sense during debugging.

Transitions, loading, and copy boundaries

Scene changes fade through black so a half-loaded texture is less obvious. A short loading screen runs on first open; textures load from relative paths next to the HTML—keep that folder structure when you deploy.

Modal text (walnut table, wine fridge, hotel-grade bedding, etc.) is staging copy written to match the pictures, not a real listing. For production real-estate use, replace every info block and hotspot label, and swap in legally cleared panoramas.

How this sits beside other demos

Travel-through parallax phone stacks 2D layers. 3D Earth is exterior observation with shaders. This article is interior equirectangular + multi-scene texture swap—closer to a virtual walkthrough tech spike. All three stay separate on the home carousel so visitors do not merge them into one fictional product.

Reuse checklist

  1. Export panoramas at 2:1; align the seam at ±180°.
  2. Edit SCENES—tune yaw/pitch live in the browser; I often place one info hotspot first to anchor direction, then clone for entry links.
  3. Publish with semantic headings, figure/figcaption around the recording (and a link to the interactive viewer), and honest scope in the lead paragraph—helps queries like 360 panorama viewer, Three.js virtual tour, equirectangular interior.

I skip a “top ten panorama plugins” roundup here. Plugins churn; documenting your scenes, hotspot graph, and deployment path ages better and reads as maintainer-written, which is what I want this archive to look like.

If you ship this on aogl.cn or your own domain, submit the article URL and the interactive viewer URL separately in Search Console—static HTML around the video and prose is what explains the tour to crawlers; the canvas alone is thin.
