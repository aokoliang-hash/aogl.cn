这篇是 aogl.cn 归档的第 9 篇原创手记，素材在 original/360-degree-panorama/。我做的是一套可嵌入的公寓内景 360° 漫游：四张 2:1 等距柱状全景图、一个 panorama-viewer.html 页面，用 Three.js 把贴图铺在「内翻」球面上，再用热点在客厅、餐厅、厨房、主卧之间跳转。不是房产中介落地页，也不教你怎么买某款 SaaS；只记我这次 Demo 的结构和取舍。

文件夹里有什么

  • Living-room.png — 北欧风客厅，落地窗对公园
  • dining-room.png — 法式餐厅，水晶吊灯与长桌
  • kitchen.png — 岛台厨房，大理石台面与铜锅陈列
  • master-bedroom.png — 主卧，城市天际线落地窗
  • panorama-viewer.html — 可全屏操作的漫游壳页

四张图都是完整一圈的室内全景：宽高比约 2:1，适合直接当 equirectangular 贴图。若比例不对，球体接缝会有一条竖线或天空/地面被拉扁——我导出前会先看一眼左右边缘能否无缝衔接。

为什么用内翻球体而不是「普通」球

Three.js 里常见写法是 SphereGeometry 再 scale(-1, 1, 1)，把相机放在球心，人看向内壁。外表面贴图时，你从外面看会像在看一颗行星；内景漫游必须「站在房间中间转头」。相机几乎固定在原点，lookAt 根据 yaw / pitch 转；拖拽改的是观察方向，不是绕物体公转。

这和本站 交互 3D 地球 同属 WebGL 球体，但地球是外观测、带光照与大气；全景漫游只要 MeshBasicMaterial 贴一张图，省算力，也避免室内全景被平行光「洗平」细节。

四场景与热点：我怎么定义跳转

panorama-viewer.html 顶部用 SCENES 数组配置场景。每个场景有 id、中文名、描述、image 文件名、初始 initYaw / initPitch，以及 hotspots 列表。

热点分四类（页面上颜色不同）：

  • entry — 进入另一个房间（例如客厅里「前往餐厅」）
  • exit — 返回上一个空间
  • info — 弹窗说明（落地窗、吊灯、城市景观等）
  • poi — 软装或物件兴趣点（沙发、岛台、衣帽间）

每个热点存 yaw、pitch（度），以及 targetScene 或 info 文案。屏幕上的圆钮位置由当前相机方向投影到 2D 算出来；背对观众的热点会隐藏，避免满屏按钮。

在线试玩（嵌入）

拖拽旋转、滚轮改 FOV、双击重置；左侧场景卡片可点；底部可上一景/下一景、开关自动轮播与缓慢自转。手机端支持单指拖、双指缩放。

四张全景静帧（对照用）

若嵌入页加载慢，仍可先看单张图理解每个空间的构图。文件名与场景 id 一一对应。

界面里还有哪些值得写进文章

顶栏显示当前场景名；左侧可折叠「漫游导航」用四张 16:9 缩略图切换。右下角罗盘指针随 yaw 旋转，和拖拽方向一致。底部显示 FOV 角度、上一景/下一景，以及自动轮播（默认约 9 秒）和慢速自转。键盘方向键可微调视角，+ / - 缩放，r 回到该场景的初始 yaw/pitch。贴图加载失败时会用带房间名的渐变画布占位，方便本地调试热点位置。

过渡、加载与「假数据」边界

切换场景时有黑色淡入淡出，避免贴图还没换完就露馅。首屏有加载条——四张图从同目录相对路径加载，部署时要保证 PNG 与 HTML 同路径关系不变。

热点里的文案（胡桃木餐桌、红酒柜、埃及长绒棉床品等）是配合画面写的示意说明，不是真实楼盘资料。若你 fork 去做真实房源，应整段替换 SCENES 与弹窗文字，并换上自己的测绘全景。

和本站其他 Demo 的关系

穿越视差手机 是分层 2D 视差；3D 地球 是外观测球体加光照。本篇是室内 equirectangular + 多场景图切换，更接近虚拟样板间技术验证。三条线并列放在首页轮播，避免混成「一个地球里有一套公寓」这种误解。

若你要复用这套壳

  1. 每张全景保持 2:1（常见 4096×2048 或 2048×1024），左右边缘对齐。
  2. 在 SCENES 里增删房间，热点 yaw/pitch 在浏览器里试调——我习惯先放一个 info 热点对位置，再复制改 targetScene。
  3. 文章页用 iframe 嵌入 + 上文说明，利于搜索理解「360 全景 / virtual tour / Three.js」。

我不在这里列「十大全景插件」对比表：插件换得快，把你自己的场景图 + 热点逻辑写清楚，比堆外链更有维护价值。
